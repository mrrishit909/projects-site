# Projects site

Static site published with GitHub Pages at https://mrrishit909.github.io/projects/. Every page is generated by `python3 build.py`
(standard library only) and the generated HTML is committed, so GitHub never runs anything.

## Publishing (private repo only, since 2026-10-19)

All work now goes to the PRIVATE repo https://github.com/mrrishit909/projects-site (git remote `private`, default branch
`unified-portfolio`). Once a change is built (`python3 build.py`) and checked in a browser, commit it and
`git push private unified-portfolio`. Do NOT push to `origin` (mrrishit909/projects, the public GitHub Pages site) and do
not merge into `main`: the owner decides separately when the public site is updated.

## Adding a project

**Rule: every project added from now on gets the same format and goes everywhere the others go.** That means a `project.json` in
the standard fields, a `cover.jpg`, the standard case-study page, an entry in the catalogue, a motion tile (`loop.mp4` +
`loop.webm`, see below), and the site-wide colours from `theme.css`. No one-off layouts, no custom pages, no per-project CSS or
colours, no `"frozen"` (only `trading-bot`, which predates the format, is allowed it). `build.py` enforces the checkable parts and
refuses to build otherwise: missing `cover.jpg`, a new frozen project, or text fields carrying `style=`, `<style>`, `<script>`,
`<link>` or `<font>`. It warns when a project has no motion tile yet; make one before publishing.

This is the whole workflow, and it is the same for every project:

1. Create `<slug>/project.json` and `<slug>/cover.jpg`. Copy the fields from any existing `project.json` (the required ones are listed
   as `REQUIRED` in `build.py`). Text fields are trusted HTML fragments.
2. Run `python3 build.py`. It writes `<slug>/index.html` (the case study) and rebuilds the home page, where the project appears as a
   new entry in the catalogue. Order is newest `date` first (`order` breaks ties).
3. Make its motion tile (next section) and its catalogue thumbnail (`python3 tools/thumbs.py`), rebuild, and check its catalogue
   entry and its case study in a browser.
4. Commit what the build changed, then publish (merge into `main`, see Publishing).

Do **not** hand-edit `index.html` or any `<slug>/index.html`: they are generated. Don't touch other projects' files when adding one.

## The motion tile (every project plays a short loop)

A project's record sleeve on the home page, and the "Next project" link on the case study before it, play `<slug>/loop.webm`
(+ `loop.mp4`). `build.py` finds them **by file name**, so nothing is declared in `project.json`.

* Every project gets one (see the rule above). Until it exists nothing breaks: the sleeve shows `cover.jpg` and the build prints a warning.
* To give a project its own tile, in the same style as the others:
  1. Copy a neighbouring file in `motion/scenes/` to `motion/scenes/<slug>.js` and redraw it for the new project.
     A scene is a pure function of the loop phase `u` (0..1); `aspect` is the card shape (1.6 to 1.85 keeps the row balanced);
     `motion/toolkit.js` has the helpers. The animation must be *about what the project is and found*, and any number drawn on it must
     come from that project's case study (the existing scenes only use figures that are on their project pages).
  2. `NODE_PATH=$(npm root -g) node motion/render.cjs --sheet <slug>` writes a 4-frame contact sheet to `motion/.sheets/` to look at.
  3. `NODE_PATH=$(npm root -g) node motion/render.cjs <slug>` writes `<slug>/loop.mp4` and `<slug>/loop.webm`.
     (Needs node, `npm i -g playwright` with its Chromium, and ffmpeg. `motion/render.cjs` has the details.)
  4. `python3 build.py`, then commit the two clips with the rest.

## How the site is laid out (so it can be changed safely)

* **`/projects/` (index.html) is the home** (redesigned 2026-10-23 from the owner's pick of three concepts, then calmed the same
  day at the owner's request: "colour scheme a bit too much", no blocks, add an intro, keep the scroll animation):
  `index.template.html` + `portfolio.css` + `home.js` (no build step; Lenis for smooth scroll). Sections: hero, Selected Work
  (four faintly tinted screens), a band linking the catalogue, about + experience (experience on a notebook page), contact
  (ink, a business card), footer. Palette at the top of `portfolio.css`: off-white `#F7F5F0`, ink `#15193A`, ONE accent, cobalt
  `#3B5BFF` (`#2B45D6` for text), used sparingly (numbers, hover, focus); each project screen gets a faint tint after the
  colour printed on its object (`--t-pass|rcpt|ruler|book`). The printed objects keep their own colours. One typeface, Archivo
  (variable width + weight, vendor/fonts, OFL). Professional facts come from the résumé at ~/portfolio/resume.pdf; do not add
  claims not in it.
* **The concept: one desk.** Every section of the home is a camera position on the same Blender desk (`tools/desk/scene.py`
  builds it; `flight.py` renders the hero's camera flight from it, `world.py` the section backgrounds and the print beat:
  `Blender -b --factory-startup -P tools/desk/world.py -- <out_dir> <w> <h> [name_prefix]`, then `cwebp -q 78` into
  `assets/world/{d,m}/`). Everything the visitor reads is a sheet of paper on it (`.paper`, one upper-left light, one shadow
  `--paper-shadow`; labels are `.stamp`). Section backgrounds are `<picture class="scene-bg">` (lazy, `d/` 2560x1600 under
  `(min-aspect-ratio: 4/5)`, `m/` 1080x2340 otherwise). The spec is `BRIEF.md`; the evidence folders are listed at the bottom.
* **The intro** (first load at the top of the page; `html.intro` set in the head, never with a hash, under reduced motion, or
  when `sessionStorage.vt` says we are returning from a case study): the first frame is a blank boarding pass close to the
  camera (`assets/world/{d,m}/print-00.webp`, the `.hero-close` picture, also the LCP element: a pixel short of the viewport
  because Chrome ignores a full-viewport image). home.js prints the figures onto it (`print-01..06`, 0.8 s), holds a beat, then
  plays the flight frames backwards 47 -> 0 over 2.6 s so the camera lifts off onto the whole desk; at 55% of the lift
  `html.intro-land` lets the frame, RISHIT (letter by letter), nav and labels rise (CSS). A Skip button, any wheel, key or tap
  ends it at once; a repeat visit in the session plays at 0.45x (`intro-again`); after 7 s it ends regardless. `intro-done`
  hides the close-up and hands the hero to scroll.
* **The hero** is a Blender render (`tools/desk/flight.py`, Blender 4.5, EEVEE: `Blender -b --factory-startup -P
  tools/desk/flight.py -- <out_prefix> <w> <h> <frames> [only_frame]`; textures in `tools/desk/tex/`, printed by
  `tools/desk/tex.html` + `shoot.cjs`): the four printed objects on a pale oak desk, the camera high and wide at first, gliding
  down onto the boarding pass. Stills `assets/flight/still-d.webp` (2560x1600) and `still-m.webp` (1080x2340, used under 4:5
  aspect, cropped at 30% from the top so portrait tablets keep the open desk under the wordmark); 48 frames each in
  `assets/flight/d/` (2560x1600) and `m/` (1080x2340), WebP q76 via cwebp, drawn on a canvas as the 280svh sticky hero scrolls.
  The RISHIT wordmark parts, "Clean. Model. Explain." passes over a veil that quiets the desk, and the flight ends in the
  boarding pass screen's tint. The nav steps away while scrolling down and returns on any scroll up (both pages).
* **Selected Work** is filled by `build.py` from `featured.json` (four slugs; area / result / contribution / caption, a `scale`
  {metric, unit, value, note}, a `screen` {object, alt} and a `sheet` {src, alt, dark}). Each screen's background is
  `assets/world/{d,m}/shot-<object>.webp` (the camera low over that object's place on the desk, the object itself hidden);
  the copy sits on an index card (`.screen-copy.paper`, stamp "01 / 04"); the printed object
  (`assets/desk/solo-{pass,rcpt,ruler,book}.webp`, cut-outs from concept C's Blender desk, `tools/desk/desk.py`) lies as HTML
  so it can lift, count up (percentages only; "31 of 31" never counts) and flip to "What I did" and "Built with"; the project's
  real chart or report (`sheet`, dark screenshots inverted to paper) slides out from under it (`--slide`) while the background
  breathes (`--kb`, 6% scale). Per-object sheet positions are in portfolio.css. The receipt's back prints like a till roll (a
  wider slip at tablet / phone widths); the ruler's back is an index card behind it. A fixed pager (prev / project name / next)
  follows the screens. Without JavaScript or under reduced motion: stills, objects upright, the sheet beside the object, the
  back printed under it.
* **Into a case study and back** (cross-document View Transitions, Chrome / Edge / Safari 18.2+; Firefox cuts): home.js names
  the clicked card's visible face `object` and its title `title` on `pageswap`, the case page's `.object` and `h1` carry the
  same names, and on `pagereveal` the home hands them back to the card `sessionStorage.vt` remembers. Flagship case studies
  open with the printed object beside the title and link back to `../#feature-<slug>`.
* **About + experience + the index card** sit on `shot-about`; **contact** sits on `shot-contact` (the desk from the other side
  of the table, the visitor's seat) with the copy on a card and the business card that leans to a fine pointer. The footer
  shows Tampa time. `404.html` (absolute `/projects/` paths; GitHub Pages serves it for any missing path) is a card on the
  about shot.
* **Case studies** (`site.css`, self-contained tokens, Archivo + Geist Mono self-hosted; theme.css is no longer loaded by
  them): the same paper, ink and cobalt; stamps for labels and step numbers; every figure a mounted plate; the next project a
  sheet. case.js is unchanged.
* **`all.html` is the complete catalogue** (`all.template.html` + `portfolio.css` + `catalog.js`): every project as a real link
  with its own thumbnail. Old addresses on the home (`#projects`, `#<slug>`, `?q=` / `?kind=`) are forwarded there by an inline
  script in the home's head, so case studies' "All projects" link (`../#projects`) and the archive redirect keep working.
* **Catalogue thumbnails.** `python3 tools/thumbs.py` (sips + cwebp) writes `assets/thumbs/<slug>.webp` at 880x503, twice the
  widest tile, cropped to the top-left 72% of the cover so its headline or chart title stays legible. True colours, no filter.
  **Run it after adding a project**, then `python3 build.py` (the build warns when a thumbnail is missing). The first row loads
  at once; the rest get their source from `catalog.js` just after the page's load event and are lazy images from then on
  (without JavaScript a `<noscript>` copy shows).
* **The catalogue** is static HTML (219 links) in a 3 / 2 / 1 column grid, so 12 always fills whole rows; `catalog.js` adds
  search + kind filter (five kind tabs with a sliding pill, synchronised with the full select; also from `?q=` / `?kind=`),
  reveal of 12 at a time on "Show more projects", and a `<dialog>` addressable as `#<slug>` with explicit history ownership
  (a click pushes one entry with `state.pushed`; Previous / Next replace it; Close steps back only over an entry this page
  pushed). `/projects/archive/` redirects to `/projects/#projects`, which forwards to `all.html`.
* **Checks:** `python3 -m http.server 8800 --bind 127.0.0.1 &` then `NODE_PATH=$(npm root -g) node tests/portfolio-check.cjs`
  (75 checks: both pages without JS, every internal link on disk, page order, the intro, the camera flight following scroll,
  each screen's number / flip / pager, the nav stepping away and back, sharp thumbnails, contrast on every colour field,
  catalogue search / tabs / filter / reveal / dialog / history, deep links and forwards, reduced motion, overflow at five widths
  on both pages, console errors). Lighthouse 12.8.2 with gzip (`npx serve@14.2.4`, port 8801): home mobile 100 / 100 / 100 /
  100, LCP 1.9 s; all.html mobile 97 / 100 / 100 / 100, LCP 2.4 s; both 100 on desktop; CLS 0.
* `theme.css` and `site.css` style the case studies (unchanged by the home redesign); `vendor/` holds Lenis, Geist, Fraunces
  and Archivo with their licences.
* Case-study pages use `site.css`. A project marked `"frozen": true` in its `project.json` is never rebuilt.
