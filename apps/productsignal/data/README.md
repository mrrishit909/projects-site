# ProductSignal data layer

* `python data/migrate.py [--reset]` applies `migrations/*.sql` in order (idempotent; each applied file's hash is recorded and a changed applied file is
  refused; `--reset` drops only this project's tables and functions). `python data/seed.py tests/fixtures/golden/inputs.json [--reference-only]` loads
  a fixture through the domain's `validate_batch` (rejected rows go to `rejected_records` with the raw row), stores the plan, the metric windows and the
  funnel definition, loads the Student t table and records a `dataset_versions` row (sha256 of the canonical JSON). Loading twice changes nothing.
  `--reference-only` loads the reference data only, so the API commands bring the log, links, assignments and exposures (`tests/support_db.py::drive`).
* **Schema** (`0001`): the twelve entities `accounts`, `users`, `identity_links`, `sessions`, `events`, `event_properties`, `subscriptions`,
  `experiment_versions`, `assignments`, `exposures`, `metric_observations`, `analysis_runs`; plus `analysis_plans`, `funnel_definitions`,
  `guardrail_reviews`, `decisions`, `metric_config`, `rejected_records`, `audit_events`, `command_results` (actor-bound idempotency),
  `dataset_versions`, and the reference tables `ps_timezones` and `t_critical_975`. Instants are `TIMESTAMPTZ`; amounts `NUMERIC`, never float.
* **Constraints** (`0002`): `assignments` unique per (`experiment_version_id`, `unit_id`); the event log, assignments, exposures, plans, reviews,
  decisions and the audit trail are append-only (UPDATE, DELETE and TRUNCATE refused by trigger); an exposure may not precede its assignment; an
  internal account cannot be assigned; valid IANA timezones; one decision per analysis run; status and variant vocabularies.
* **`sql/reference_metrics.sql`** recomputes every key of `expected.json` (and `tracking_quality`, `identity`) from the FACTS in one statement, with no
  stored status, result or derived column (`%(cutoff)s`, `%(xv)s`, `%(run_id)s`). Exact NUMERIC throughout; square roots at 40 decimals; the chi-square
  p-value is computed in SQL by the Maclaurin series of erf at 90 decimals. The Student t quantile cannot be reproduced in SQL, so the SQL computes the
  mean, variance, standard error and bounds and reads the quantile from `t_critical_975`, generated by Python (`sql/generate_t_quantiles.py`, df 1..2000,
  20 decimals, bisection on the exact CDF); `tests/test_sql_reference.py` checks the table against textbook values and the exact quantile. With no
  table row for a df the interval is null, never wrong.
* `tests/test_sql_reference.py` checks the SQL against the three fixtures, the domain on a rich population and on seeded random populations, and that
  scrambling every stored status changes nothing.
