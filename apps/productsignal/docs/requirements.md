Organising question: **should an onboarding change ship, stop, or receive more investigation?** (P06-GOAL-01). ## 1. User stories and acceptance criteria
1. **As a product analyst** I open the journey overview and see, for the as-of 2026-10-05T00:00:00Z, the twelve metrics with their windows, populations and exclusions, and can move the cutoff to any of the five runs and see what that run saw.
   *Accept:* the six metric keys equal the independent reference on the snapshot (`data/sql/reference_metrics.sql` against the Python domain at every read; 2,519 TypeScript golden checks; the reconciliation of `sql-analysis.md` section 9: 296 rows equal).
2. **As an experimentation analyst** I see the known answer reproduced before any volume: 20 of 100 control and 30 of 100 treatment mature accounts activate, 0.200000 and 0.300000, +10.00 pp, relative 0.500000, a Newcombe interval of -0.020249 to +0.216734 that includes zero, so not conclusive; 5 of 20 mature accounts return on exact day 7 in their own timezone (0.250000).
   *Accept:* equal in the Python domain, the SQL reference, the TypeScript domain, the standard-library oracle `tests/reference_check.py` (ALL OK, 706 checks), `expected.json` and the workbook's `Golden case` sheet.
3. **As an experimentation analyst** I read the sample ratio before any lift: v1 passes (200 / 200) and v2 is a MISMATCH (62 / 92 against 0.60 / 0.40, chi-square 25.004329) and shows no lift.
   *Accept:* `test_08_a_sample_ratio_mismatch_blocks_ship`, `test_c10_a_sample_ratio_mismatch_blocks_ship_and_stop`, the result page's v2 panel, the `Metrics` sheet's `withheld` rows for run an-005.
4. **As an experimentation analyst** I cannot present an interim run as final, and a late event or a row dated after a run's cutoff cannot change a published result.
   *Accept:* `test_03_an_interim_result_presented_as_final_cannot_support_ship`, `test_06_a_late_event_changes_only_a_later_run_and_the_revision_is_disclosed`, `test_domain_ignores_rows_dated_after_the_cutoff`; the first interim run counts 155 accounts.
5. **As a product manager** I record ship, stop or inconclusive citing one run and its review; the rules refuse an interim run, a mismatch, a harmful guardrail, a plan deviation and a hash mismatch, every refusal is audited, and nothing ships from it.
   *Accept:* `test_c10_records_a_ship_decision_citing_the_run_and_the_review_and_changes_no_product_state`, `test_R6_07_every_refused_decision_leaves_an_audit_row`.
6. **As a tracking owner** I see what the log lost, duplicated or delivered late, by week.
   *Accept:* 124 duplicates, 237 delayed, 30 unknown, 305 bot and 114 internal rows of 12,552 (`sql-analysis.md` investigation 04; the tracking page).
7. **As a data analyst** I can rebuild the headline measures from CSV exports and compare them with the independent recomputation.
   *Accept:* the measures recomputed from `artifacts/bi/*.csv` equal `reference_metrics.sql` and the domain (`bi-package.md`).
8. **As a reader of the evidence** I see what is built, what is simulated in browser memory and which results are conclusive only by a hair.
   *Accept:* the case-study route, `executive-memo.md` and this file say so (section 5).

## 3. Non-functional requirements
| ID | Requirement | How it is met |
|---|---|---|
| NFR-01 | Deterministic synthetic data: the same seed gives the same bytes; size under 5 MB | `data/generate.py` seed 20261026, byte-identical under three `PYTHONHASHSEED` values (`test_deterministic_across_runs_and_hash_seeds`); 3.6 MB (`test_total_size_is_under_5_mb`) |
| NFR-02 | Exact arithmetic: Decimal and Fraction in Python, BigInt rationals in TypeScript, exact numerics in SQL; no float in a published figure | `test_domain_source_has_no_float`, `test_expected_json_has_no_float_numbers`, `test_amounts_are_exact_numeric_never_float` |
| NFR-03 | Idempotent commands bound to actor, role, payload and dataset version; 409 for a reused key, a stale dataset version or a deadlock after three attempts; 422 with a code; never a stack trace | `test_the_key_is_bound_to_the_payload_the_actor_and_the_role`, `test_dataset_version_is_part_of_the_payload_and_a_stale_version_is_refused`, `test_a_deadlock_is_retried_three_times_then_409_concurrent_update` |
| NFR-04 | Atomic audit: the effect, the audit row and the stored result are one transaction; a failed command leaves no trace | `test_a_command_and_its_audit_row_commit_together_or_not_at_all` |
| NFR-05 | Concurrency: lock order idempotency key, experiment-version rows, unit rows; two assignments or two decisions race: exactly one stands | `test_two_threads_assigning_one_unit_leave_one_assignment`, `test_two_concurrent_decisions_on_one_run_leave_one_decision`, `test_the_same_idempotency_key_raced_executes_once` |
| NFR-06 | Authorization on the verified backend: 401 without an identity, 403 for a forbidden role; the public site claims no access control | `test_commands_need_an_actor_and_a_known_role`, `test_role_inventory` |
| NFR-07 | The cutoff rule: a run sees only the facts that existed by its cutoff, in the domain, the SQL reference and the API | D-08; `test_domain_ignores_rows_dated_after_the_cutoff`, `test_sql_reference_ignores_rows_dated_after_the_cutoff`, `test_api_metrics_and_commands_ignore_rows_dated_after_the_cutoff` |
| NFR-08 | Server-stamped fact instants: `assigned_at`, `exposed_at` and `decided_at` are the API clock; only an admin with `backfill: true` may state one, and the audit row records it | D-10; `test_R6_05_facts_are_stamped_with_the_server_clock_and_only_an_admin_may_backfill` |
| NFR-09 | Timezone independence: the SQL reference gives the same answer under any session TimeZone (hour-based intervals) | `test_R6_03_the_sql_reference_gives_the_same_answer_in_every_session_time_zone` |
| NFR-10 | Accessibility and responsiveness: four widths (360, 768, 1280, 1920) and 200% zoom, no horizontal overflow | `web/e2e/screens.spec.ts` (65 screenshots, `web/evidence/index.json`) |
| NFR-11 | No credentials, real personal records or secrets in any artifact; synthetic label visible | the artifact documents hold placeholders only (the local development login of the CI workflow is never written into them); `tests/test_artifacts.py` |
| NFR-12 | Hosted compute and durable evidence: backend on a `postgres:16` service, static build on a hosted runner | `.github/workflows/productsignal-ci.yml`; `artifacts/CHECKSUMS.txt` |
| NFR-13 | Reproducible artifacts: every artifact number is reproducible by a named command and reconciled to an independent source | `data/sql/analysis/run_all.py` (296 reconciliation rows), `tests/test_artifacts.py` |
