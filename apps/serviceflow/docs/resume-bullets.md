Based on what was built and verified (the verification ledger, `uat-evidence.md`, this package's reconciliation and tests) and consistent with the public case study (`/serviceflow/project.json`). The project uses **synthetic data only**; no bullet claims business impact, adoption, time or cost savings, or users.
Professional facts outside this project belong to the resume, not to this file. Wording stays inside the case study: no figure appears here that is not in it or in `sql-analysis.md`.

* Wrote eight executable SQL investigations on a seeded synthetic snapshot (arrivals by hour of week, waits and P90 by queue and priority, SLA compliance with open overdue apart, occupancy by agent and shift with breaks, transfer and reopen effects, abandonment by channel, survey response skew, rejections and injected defects), each figure reconciled to an independent SQL reference and the Python domain through 185 reconciliation rows.
* Built a formula-driven analyst workbook (live formulas, a full / training / holdout switch) recalculated by LibreOffice headless and compared with the domain, and a BI package (star schema, CSV exports, DAX-style measures recomputed in Python and reconciled); stated plainly that Excel and Power BI Desktop were not run and that no `.pbix` exists.
* Wrote an executive memo that keeps observed, simulated and hypothetical results apart: three seeded scenarios with 50 replications each and 95 % intervals, a paired difference on shared demand paths (-10.9 +- 3.4 minutes of simulated mean wait), and the model's stated limits (dedicated servers, a single queue, synthetic data).
* Packaged the work for review: data dictionary and ER diagram, UAT evidence with the route list and screenshot names, a technical case study that lists open gaps and findings, and a checksummed release package with a rollback manifest.
