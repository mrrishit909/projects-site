Kin: remember people, keep the notes private

Remember the people who matter, and keep what you write about them private.

01 — The problem

One person wants a private place to keep track of relationships, important dates, interactions and a journal, without it being shared, tracked or locked into a vendor.

Defining workflow: Add a person and a birthday, record an interaction, write a journal entry offline, reconnect and resolve a conflicting revision without silent overwrite, export everything, and delete a person under a clear policy.

02 — What I built

One of eleven independent CRM MVPs in a single monorepo, each with its own database, migrations, tests and review packet. This one is inspired by Monica and is called Kin.

  • Person profiles, relationships with inverse labels, important dates with timezone-aware reminders, interactions timeline, tags
  • Private journal with person mentions and versioned edits (a conflict shows both versions; nothing is overwritten silently)
  • Opt-in offline journal drafts in the browser with local-only and synced states, purged on sign-out
  • Complete export, person deletion policy, account deletion with password and typed phrase

03 — How it was built

  1. 01

    Specify before building

    An acceptance document names the persona, the bounded scope, what is deferred, and ties every required feature to evidence (a test, an end-to-end journey or a recorded check).

  2. 02

    Model the database so the rules hold even if the code is wrong

    A Prisma schema plus a hand-written migration of CHECK constraints, composite foreign keys that pin every record to its workspace, and triggers. The tests try to break these from raw SQL.

  3. 03

    Build the distinguishing workflow through every layer

    Person profiles, relationships with inverse labels, important dates with timezone-aware reminders, interactions timeline, tags

  4. 04

    Prove it in a fresh clone

    20 gate checks pass and 0 fail in a fresh clone of commit 55ab57c54c: 7 unit, 29 integration against a real PostgreSQL, 18 browser tests on the production build, container start, a live black-box check, restart persistence, backup and restore, and a production-dependency audit.

  5. 05

    Review it as an independent reader would

    A review packet lists what is implemented, what is measured, what was fixed on the way, and every known limit and release blocker, so nothing here is claimed beyond its evidence.

05 — What I'd do next

  • Single owner per private workspace: no sharing, no teammates
  • Not end-to-end encrypted: protection relies on host disk encryption and access control; offline drafts in the browser are readable by anyone with the browser profile (stated in the app)
  • Reminders are shown, never sent; no import, uploads or integrations
  • Not production-ready: no TLS, proxy or monitoring provisioned
