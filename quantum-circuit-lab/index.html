What Does Entanglement Look Like Gate by Gate?

A browser quantum circuit lab where every step of a gate is drawn as the real state partway through it: Bloch spheres that shrink as qubits entangle, pairwise entanglement drawn from the state, shots with exact noise, and a mock 5-qubit backend that needs 10 SWAPs for Grover search and drops it from 94.5% to 39.9%. The simulator is Rust compiled to WebAssembly, 2.5–2.8× faster than TypeScript.

01 — The problem

Quantum states are hard to teach because they are long lists of complex numbers. A circuit diagram shows what was done, and a histogram shows what came out, but not what happened in between. Can a browser lab show the state itself, at every moment of every gate, and stay honest about what is real?

The build book's rule for this volume is that motion has to carry meaning: here every animated position is the actual state partway through a gate. Blueprint 9 of ten, built as its demo scenario end to end.

02 — What I built

A Next.js lab that runs entirely in the browser, and a Fastify API on PostgreSQL behind the same interface, started by one docker compose up.

  • A state-vector simulator with two kernels, written in Rust compiled to WebAssembly and run in a Web Worker, checked against an identical TypeScript kernel.
  • Fractional gates (Ut from each gate's eigen-decomposition), so stepping animates real intermediate states.
  • Bloch vectors from each qubit's reduced state and pairwise entanglement (negativity of the partial transpose).
  • A stabilizer simulator for large Clifford circuits and an exact density-matrix noise model.
  • A hardware-adapter interface with a mock 5-qubit backend: Toffoli decomposition, SWAP routing, a queued job, and an outage it survives.
  • A circuit editor with drag and drop and a full keyboard path, deep links, reduced motion and a list view.

03 — How it was built

  1. 01

    Interpolation that is physics, not tweening

    Stepping through a circuit tweens the drawn position, but what is drawn at position 1.5 is the state after the first gate and half of the second: CNOT0.5, computed from the gate's eigenvalues. Halfway through the CNOT the Bell pair's negativity is already 0.354; at the end both Bloch vectors have length 0 and the negativity is 0.50. A linear blend of start and end states would leave the sphere and is not a state at all. (The one blend in the lab is the measurement-collapse animation, which moves the arrows to the measured poles.)

    // U^t = sum_k lambda_k^t v_k v_k^dagger (principal branch)
const mt = t >= 1 ? m : power(m, t);
k.apply1(s, target, controls, mt);
  2. 02

    Entanglement you can see, and when you can't

    Each arrow is one qubit's reduced state: on the surface when pure, at the centre when maximally entangled. The arcs between spheres are the negativity of each pair's reduced density matrix. A four-qubit GHZ state is the useful surprise: every arrow sits at the centre, yet all six pairs have negativity 0, so no arcs are drawn. The entanglement is real, but it belongs to all four qubits together, not to any pair. The scroll intro ends on exactly that picture.

  3. 03

    Rust in the worker, checked against TypeScript

    The two kernels (a 2×2 gate under a control mask, and the SWAP family) are 20 KB of WebAssembly exported without wasm-bindgen; states can live in WASM memory so gates run in place. On 100 random circuits of 1–10 qubits the two kernels agree to 10−12. With the same loop structure, WASM is 2.5–2.8× faster from 12 qubits up (24 qubits: 1.78 s vs 0.67 s per layer). A SIMD build was no faster, so it is not shipped.

  4. 04

    Simulators that check each other

    Seven reference circuits match their textbook distributions within 10−12, and Grover's two iterations on three qubits give 94.5% (0.9453125) on the marked item. The stabilizer simulator agrees with the state vector on 60 random Clifford circuits and runs a 500-qubit GHZ in about 3 ms; a full 500-qubit measurement takes about 0.3 s, because measurement is quadratic, so the first comment claiming milliseconds was corrected.

  5. 05

    Noise, exactly

    Noise is simulated with a density matrix stored as a 2n-qubit vector, so the same kernel applies the gate and its conjugate. Each channel is checked against its textbook effect, traces stay at 1, and noisy shots pass a chi-square test against the exact noisy distribution. At the lab's default noise (1% and 3% depolarizing, 2% damping per step, 2% readout) the Bell distribution moves 9.2%, while Grover's marked item falls from 94.5% to 30.2%.

  6. 06

    A mock backend that behaves like hardware

    Linden-5 has five qubits in a line. Submitting Grover-3 decomposes its Toffolis into CNOT and T gates, then routes it: a greedy router with lookahead needs 10 SWAPs, 34 two-qubit gates and depth 64, and the marked item comes out 39.9% of the time. The first, naive router needed 15 SWAPs and got 37.7%. Jobs go through a queue shared by every organization; with the backend offline the job is held and retried, not lost, and completes when it returns.

    const mover = cost(moved(layout, la, lb), idx + 1) <= cost(moved(layout, lb, la), idx + 1) ? la : lb;
  7. 07

    The same lab behind an API

    In Docker the lab saves versioned circuits, runs shots on the server (on the same Rust kernel) and submits hardware jobs through the API: bearer tokens with roles, row-level security per organization, idempotency keys, an hourly hardware quota, read-only share links, a hash-chained audit log, OpenTelemetry spans, and completion e-mails to a local mail sink. Testing it found a pagination bug: the cursor carried a millisecond timestamp while Postgres stores microseconds, so page 2 repeated page 1.

05 — What I'd do next

  • Trajectory (Monte Carlo wavefunction) noise to go past 10 noisy qubits, checked against the density matrix where both run.
  • A correlated two-qubit depolarizing channel instead of independent one-qubit channels on each qubit a gate touches.
  • Mid-circuit measurement with classical feed-forward, so teleportation needs no deferred-measurement trick.
  • A routing search better than greedy lookahead (Grover-3 still needs 10 SWAPs on a line of five).
